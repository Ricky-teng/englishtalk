## v2.10 — 2026-10-11

**備援 AI（對話不會斷）**
- 每次呼叫都有候選名單（只列有金鑰的）：對話 = 主要的對話模型 → 同一家另一個快速模型（額度分開算）→ 另一家的對話模型；查字等 = 查字模型 → 對話模型 → 另一家

- 已經念出一部分的回覆不會中途換備援（避免重複），就以念到的部分為準

**AI 用量**
- 每次呼叫（含失敗）記下供應商、模型、用途（對話／文法／查字等）、token（供應商回報的實際數字，拿不到才估計），保留 31 天

- 最近 7 天的呼叫次數長條圖，附數字表格

## v2.9 — 2026-10-11

**儲存改用 IndexedDB**
- 資料從 localStorage（上限約 5MB）搬到瀏覽器內建資料庫 IndexedDB，容量通常是幾百 MB 到好幾 GB
- 第一次打開新版自動搬移：確定寫進資料庫後才刪掉舊的 localStorage
- 啟動時整份讀進記憶體，其餘程式完全不用改；修改後 400ms 合併寫回
- 切到背景立刻寫；關分頁或重新整理時另外同步暫存到 localStorage，下次打開以「比較新的那份」為準（同時開兩個分頁也不會互相蓋掉）
- 向瀏覽器申請「持久儲存」，空間緊張時不會被自動清掉（安裝成 App 通常會直接同意）
- 不能用 IndexedDB 的瀏覽器（少數無痕模式）自動退回 localStorage，功能照常
- 空間變大後，上限跟著放寬：對話紀錄 200 → 2000 場、查詢快取 3000 → 30000 筆、作答紀錄 6000 → 50000 筆
- 「紀錄」頁的備份區顯示儲存空間：存在哪、用了多少、這台裝置還能用多少、是否已設為不會被清除

## v2.6 — 2026-10-09

**Groq 穩定性**
- 送出前先在本機排隊：依模型估算這一分鐘已用的請求數與 token（保守取免費額度的 85%），不夠就等；對話最多等 1.5 秒、查字最多 25 秒、文法與補詞性等背景工作讓路

- 要 JSON 陣列的請求包成 `{"items":[...]}`，讓 Groq 也能開 JSON 模式；JSON 驗證失敗時自動關掉 JSON 模式重要一次
- 單次 max_tokens 上限 2400、批次查詢每 6 個字一批，避免單一請求就超過每分鐘額度
- 429 依 retry-after（讀得到時）等待；Failed to fetch 在 Groq 多半是被限流，改成等 2.5 秒、10 秒再重試
- 收到回應後用實際 token 用量更正本機帳本

## v2.1 — 2026-10-07

**多種複習方式**（全部不用出聲，翻卡仍是預設）
- ✅ 看英選中、🔁 看中選英：干擾選項同詞性優先、太像的中文會排除；答對自動跳下一題，1–4 鍵作答
- 🧩 例句填空：要填出句子裡的正確詞形（negotiated）；只打原形算對但會提醒
- ⌨️ 拼字、🎧 聽寫：差一個字母算「差一點」；答錯可以照打一次加深印象；提示一次多給一個字母
- 🔀 混合（推薦）：依熟練度自動換題型，新字先認、熟了再逼你寫；錯的字這輪最後用較簡單的題型再考一次
- 🎮 配對遊戲：限時配對、記錄最佳成績，只是暖身，不影響複習排程
- 作答前整張題目卡不能點字查詢，避免偷看答案
- 所有作答（含翻卡、用說的）都會記錄題型與作答時間，給個人分析用

**個人分析**（紀錄頁，全部在本機計算）
